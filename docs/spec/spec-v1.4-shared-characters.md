# 追加仕様書 v1.4 — 共通キャラ設定（ピン / 全プロジェクト共有）

対象バージョン: v1.4.0
作成日: 2026-05-25
基底ドキュメント: requirements.md / design.md / spec-v1.1 / spec-v1.2 / spec-v1.3 / ADR-001
ステータス: **確定（2026-05-25。データモデル=ワークスペース共通プール / 保存時=含めて書き出す / UI=上部にピン留め表示・固定ボタンは SVG。かしぇ確認済み → 実装着手）**

---

## 1. 追加背景

- 霊夢・魔理沙のような**毎回登場するキャラクター**を、台本（プロジェクト）ごとに登録し直すのは手間。
- キャラに「**固定（ピン）**」を立てておくと、**タブをまたいで全プロジェクトでデフォルトで使える**ようにしたい。
- v1.3 で複数台本をタブ管理できるようになったため、「タブ横断で共有されるキャラ」を自然に表現できる土台が整っている。

---

## 2. 確定した設計判断（着手前に確認済み）

| # | 論点 | 決定 |
|---|---|---|
| 1 | 共通キャラのデータの持ち方 | **ワークスペース共通プール**。ピンしたキャラは `Workspace` 直下の共有プールに移り、全タブ・新規タブに自動で並ぶ。名前/色の編集は全タブに即反映。`Project` は `.ymscript` 互換のまま不変、ピンはワークスペース側に保持（v1.3 と同思想） |
| 2 | `.ymscript` / Markdown 保存時の扱い | **含めて書き出す**。その台本が参照する共通キャラも `characters` に materialize してファイル単体で自己完結（YMM4/再読込で困らない）。読み込み側ではローカル扱い（ピン状態はファイルに持たない） |
| 3 | UI / 操作 | **キャラ一覧の上部に共通キャラをまとめてピン印付きで表示**。各キャラ行に**固定トグルボタン（インライン SVG・絵文字不可）**。ローカルキャラはその下 |

## 4. データモデル

`Project` 型・`.ymscript` 形式は**変更しない**（互換維持）。共通キャラは `Workspace` に持たせる。

```typescript
type Workspace = {
  version: 1;
  activeId: string;
  entries: WorkspaceEntry[];
  pinnedCharacters: Character[]; // 新規: 全プロジェクト共有の共通キャラ
};
```

- **実効キャラ一覧（effective characters）**: あるプロジェクトを編集中のとき、UI・名前解決・ドロップダウンで使うキャラの全体は
  `effective = [...workspace.pinnedCharacters, ...activeProject.characters]`（**共通が先、ローカルが後**）。
- **id の一意性**: ピンは「コピー」でなく「移動」。1つの id は共通プールかどこかのプロジェクトのローカルか、**どちらか一方**にだけ存在する（実効一覧内で重複しない）。
- **不変条件**: あるプロジェクトの実効一覧は最低1キャラ（最後の1キャラ削除不可ガードは実効一覧に対して適用）。
- **後方互換 / マイグレーション**: 既存ワークスペース（`pinnedCharacters` 無し）や旧単体プロジェクトからの移行時は `pinnedCharacters: []` を補う。`parseWorkspaceFile` は `pinnedCharacters` が無ければ `[]`、配列だが要素不正なら検証で弾く。

## 5. 状態設計（useProject 拡張）

内部 `Workspace` に `pinnedCharacters` を追加。公開 API を拡張する（既存 mutator は概ね不変、ルーティングのみ追加）。

公開するもの（追加・変更）:
- `characters: Character[]` — **実効一覧**（共通 ∪ アクティブ project のローカル、共通が先）。行ドロップダウン・LineRow・CSV/Markdown 名前解決はこれを使う。
- `pinnedCharacters: Character[]` — 共通キャラ（CharacterPanel の上部グループ表示・ピン判定用）。
- `pinCharacter(id): void` — アクティブ project のローカルキャラを共通プールへ移動（末尾追加）。既に共通なら no-op。
- `unpinCharacter(id): void` — 共通キャラをアクティブ project のローカルへ移動（末尾追加）。**他プロジェクトでそのキャラを参照していた行**は、共通プールから外れて参照不能になるため、`deleteCharacter` と同様に各プロジェクトの fallback（そのプロジェクトの実効一覧先頭、無ければ `""`）へ付け替える（dangling／孤児行を残さない）。アクティブ project の行はローカルに移ったキャラを引き続き参照する。

ルーティング（pinned かローカルかで作用先を切替）:
- `renameCharacter(id, name)` / `setCharacterColor(id, color)` — id が共通プールにあれば**共通プールを更新**（= 全タブ反映）、なければアクティブ project のローカルを更新。
- `addCharacter(name)` — **アクティブ project のローカル**に追加（色は実効一覧の長さ基準で付与し衝突回避）。固定はユーザーが後からボタンで行う。
- `deleteCharacter(id)`:
  - ガード: 実効一覧が1キャラ以下なら no-op（最後の1キャラは削除不可）。
  - id が共通プールにある場合: 共通プールから除去し、**全プロジェクトのライン**でその id を参照する行を各プロジェクトの fallback キャラ（除去後の実効一覧の先頭。無ければ `""`）へ付け替える（共有エンティティ削除＝全タブで dangling を残さない）。
  - id がローカルの場合: 既存挙動（アクティブ project のローカルから除去、参照行を fallback へ）。

全 mutator は安定参照を維持（React Compiler 有効だが既存方針踏襲）。

## 6. 入出力での名前解決・materialize

- **CSV / Markdown / 1行コピー / 行のキャラ名表示**: すべて**実効一覧**（共通 ∪ ローカル）で `characterId → name/color` を解決する（F-126）。共通キャラのセリフが名前なしにならないようにする。
- **`.ymscript` / Markdown 保存（F-125）**: 書き出す `characters` を materialize する。
  `charactersForExport = [...activeProject.lines が参照する pinnedCharacters, ...activeProject.characters]`（重複なし）。
  - 参照されている共通キャラのみ含める（未使用の共通キャラはそのファイルには書かない）。
  - 結果として `.ymscript` / `.md` はファイル単体で完結（YMM4 CSV 取込・再読込で名前が解決できる）。
- **読み込み（`.ymscript` / `.md` を新規タブで開く）**: ファイル内 `characters` を**現在の共通プールと名前で照合**してから取り込む（F-128）。
  - ファイル内キャラと**同名（trim 後一致）の共通キャラが既にある**場合: そのキャラはローカルに重複追加せず、**ファイル内の行参照（characterId）を共通キャラの id へ付け替える**。名前・色などの定義は**共通側を優先**（共通が全タブの正）。
  - 同名の共通キャラが**無い**キャラのみ、新規プロジェクトのローカルとして取り込む（id はファイル由来 or 新規採番）。
  - これにより、共通キャラ（例: 霊夢）を含む台本を読み込んでも**同名キャラが二重に並ばず**、行が既存の共通キャラに正しく結び付く。ピン状態自体はファイルに持たないため、新規ローカルとして入ったキャラはユーザーが必要なら再度ピンする。

## 7. UI / コンポーネント設計（CharacterPanel）

- キャラ一覧を**2グループ**に分けて表示:
  1. **共通キャラ（pinnedCharacters）** — 一覧の**上部**にまとめる。各行にピン印（固定中であることを示す SVG）。共通キャラが0件ならグループ見出しは出さない（または非表示）。
  2. **このプロジェクトのキャラ（ローカル）** — その下。
- 各キャラ行の構成（既存）: 色ドット（クリックで ColorWheel）/ 名前（ダブルクリックでインライン編集）/ × 削除。これに加えて:
  - **固定トグルボタン**: **インライン SVG のピン（画鋲）アイコン**（F-124、絵文字禁止）。
    - 状態: 固定中＝塗り（active 色 = cyan 系）、未固定＝アウトライン（淡色）。`aria-pressed` でトグル状態を表現、`aria-label` は「共通キャラに固定」/「固定を解除」。
    - `fill="currentColor"` 等で配色・状態を CSS から制御（cold-blue-black に馴染ませる）。
- ピン/解除でキャラがグループ間を移動する際は、既存の追加/削除アニメ（appear-slide / フェード）に倣い軽く動かしてよい。`prefers-reduced-motion: reduce` 尊重。
- 既存の「最後の1キャラ削除不可」「色編集（HSV カラーサークル）」「名前インライン編集」はそのまま、対象が共通/ローカルどちらでも動くようにする。

### 7.1 既存コンポーネントへの影響
- **LineRow / ScriptEditor**: 受け取る `characters`（実効一覧）をそのまま使う（無改修〜最小）。共通キャラもドロップダウンに出る。
- **CSV/Markdown/保存ロジック**: 名前解決を実効一覧に、保存は materialize に対応（§6）。
- **App**: `useProject` の新 API（pinnedCharacters / pinCharacter / unpinCharacter）を CharacterPanel へ配線。

---

## 8. 永続化 ＆ マイグレーション

- ワークスペース永続化に `pinnedCharacters` を含める（既存の単一 `:workspace` キーにそのまま）。
- 復元時 `parseWorkspaceFile`: `pinnedCharacters` 欠落 → `[]`。要素は `Character`（id/name/color）として検証、不正なら既定ワークスペースへフォールバック（既存方針）。
- 旧キー（単体 Project）からの移行時は `pinnedCharacters: []`。

---

## 9. スコープ外（今回）

- 共通キャラの並べ替え（D&D）。
- 「共通キャラだけ別ファイルに書き出す/読み込む」専用 I/O（共通はワークスペースに保持）。
- プロジェクトごとに「この共通キャラはこのタブでは隠す」といった部分的オプトアウト（全タブ一律で出す）。
- 複数ワークスペース。
