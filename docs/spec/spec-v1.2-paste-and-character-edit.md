---

## 1. 追加背景

1. **プレーンテキストの一括流し込み**: LLM 出力やメモ帳の「セリフだけのベタテキスト」を、Markdown 形式（`名前: セリフ`）を作らずに、改行区切りのまま一気に行へ取り込みたい。
2. **キャラクターの後編集**: 現状、名前は追加時のみ・色は自動付与で固定。あとから**名前の修正**と**色のカスタム**をしたい。
3. **破壊的操作の安全なリセット**: 台本を白紙からやり直したいとき、**全行を一括で消したい**。ただし誤操作防止に、ブラウザ標準の確認ダイアログではなく**独自デザインの確認モーダル**を挟む。
4. **アニメーションの充実（横断要件）**: v1.2 で**追加する各機能（コピペモーダル・名前編集・色相環・全行リセット確認）にもアニメーションを行き渡らせ**、既存の演出水準（FLIP・appear-slide・オープニング等）と揃える。詳細は §4.7。

## 2. 機能要件

### 2.1 コピペでインポート（プレーンテキスト → 行）

| ID | 要件 | 優先度 |
|---|---|---|
| F-70 | ヘッダーに「**コピペでインポート**」ボタンを追加する | 必須 |
| F-71 | クリックで**テキスト入力モーダル**を開く（複数行 textarea ＋「取り込み」「キャンセル」） | 必須 |
| F-72 | 入力テキストを**改行で分割**し、各行を1セリフ行として取り込む | 必須 |
| F-73 | 取り込んだ行のキャラクターは**すべて先頭（初期）キャラクター**に割り当てる | 必須 |
| F-74 | 取り込みは**既存台本の末尾に追加**する（置換しない）※§7-1 | 必須 |
| F-75 | **空行はスキップ**する（前後の空白も trim）※§7-2 | 推奨 |
| F-76 | キャラクターが0人のときは「**キャラ1**」を自動作成してから取り込む ※§7-3 | 必須 |

**動作イメージ**（要望どおり）:

```
入力（モーダルに貼り付け）        取り込み後のエディタ
─────────────────────        ─────────────────────
あいうえお                       キャラ1: あいうえお
かきくけこ              →        キャラ1: かきくけこ
さしすせそ                       キャラ1: さしすせそ
```

| ID | 要件 | 優先度 |

## 3. データモデルへの影響

- 既存の型 `Character { id; name; color }` / `Line { id; characterId; text }` は**変更なし**（新フィールド不要）。
- `useProject` に mutator を追加（いずれも安定参照＝useCallback、localStorage 自動保存は既存の仕組みに乗る）:
  - `renameCharacter(id: string, name: string): void`
  - `setCharacterColor(id: string, color: string): void`
  - `importPlainText(text: string): number` — 末尾追加。先頭キャラへ割当て。0人なら既定キャラを作ってから。返り値 = 取り込んだ行数。
  - `clearAllLines(): void` — 全セリフ行を削除（`lines` を空に）。キャラクター・プロジェクト名は保持（F-103）。
- 色・名前の変更は `characterId` 参照を壊さないため、既存の行データはそのまま維持される。

## 4. UI / コンポーネント設計

### 4.1 Header（コピペインポート ボタン）

- 「全件コピー」付近に「コピペでインポート」ボタンを追加。クリックで `PasteImportModal` を開く。
- ※既存の保存▾/読込▾メニューとは別の独立ボタン（コピペは頻用想定）※§7-5。

### 4.2 PasteImportModal（新規コンポーネント）

- `role="dialog"` `aria-modal="true"` `aria-label="テキストをコピペでインポート"`。
- 中身: 説明文（「改行ごとに1行・先頭キャラに割り当て」）＋複数行 `textarea`（オートフォーカス）＋「取り込み」「キャンセル」。
- 取り込み実行で `importPlainText(textarea.value)` を呼び、結果（n 行追加）を簡易通知してモーダルを閉じる。
- Esc / オーバーレイクリック / キャンセルで閉じる。フォーカストラップ。閉じたらトリガーボタンへフォーカス復帰。

### 4.3 CharacterPanel（名前編集・色編集）

- **名前**: 現状の `<span class=name>` を、ダブルクリックで編集用 `<input>` に切り替え（CharacterPanel 内 local state `editingId`）。Enter/blur で `renameCharacter`、Esc でキャンセル。
- **色ドット**: 現状の装飾 `<span class=dot>` を**ボタン化**（`aria-label="{name} の色を変更"`）。クリックで `ColorWheel` ポップオーバーを開く。`setCharacterColor` で確定。
- 「最後の1キャラは削除不可」等の既存制約は維持。

### 4.4 ColorWheel（新規コンポーネント・依存ゼロ）

- 外部ライブラリを使わず自前実装（NF-33 オフライン/依存最小に従う）。
- 構成案: 
  - **色相環**: `conic-gradient(hsl(0..360))` で円環を描画、クリック/ドラッグの角度から hue（0–360）を算出。
  - **明度スライダー**（＋必要なら彩度スライダー）: hue を固定し L（/S）を調整。
  - **hex 入力欄**: 直接入力でき、キーボードだけでも色指定可能（a11y 確保）。
  - 内部は HSL で保持し、出力時に hex へ変換（`#RRGGBB`）。
- ポップオーバーは色ドットの近傍に表示。外側クリック/Esc で閉じる。

### 4.5 ConfirmDialog（独自確認モーダル・新規）

- 全行リセットの確認に使う。`role="alertdialog"` `aria-modal="true"` `aria-labelledby`（タイトル）`aria-describedby`（本文）。
- 構成: タイトル（例「全行をリセットしますか？」）＋本文（例「すべてのセリフ行が削除されます。この操作は元に戻せません。」）＋ボタン「キャンセル」「リセット」。
- **「リセット」は破壊操作色（`--danger`）**。**既定フォーカスはキャンセル**（F-102）。Esc / オーバーレイクリック / キャンセルで閉じる。フォーカストラップ、閉じたらトリガーへ復帰。
- 汎用化して、PasteImportModal と**共通のモーダル基盤**（オーバーレイ・トラップ・Esc・アニメ）を再利用するのが望ましい（`Modal` ベース ＋ confirm/paste の中身違い）。

### 4.6 全行リセット ボタンの配置

- ヘッダーの操作エリア（保存/読込/全件コピー付近）か、台本エディタのツール域に「全行リセット」を置く。破壊操作なので**控えめな見た目＋danger 系ホバー**にし、誤クリックを避ける。0行時は disabled（F-104）。

### 4.7 アニメーション設計（v1.2 各機能・横断要件 §1-4）

design-library のアニメを使い、追加機能すべてに演出を行き渡らせる。すべて **prefers-reduced-motion で簡素化/即時**、装飾は `aria-hidden`。

| 対象 | 開く/入場 | 閉じる/退場 | 採用（design-library） |
|---|---|---|---|
| PasteImportModal / ConfirmDialog | オーバーレイ **backdrop-fade**（opacity, ~180ms）＋ パネル **modal-rise-in**（translateY 8px→0 + opacity, ~0.28s ease-out, わずかに scale 0.98→1） | フェードアウト（余韻短め ~160ms） | modal-family（fukujo / ssense） |
| モーダルの閉じる「×」ボタン | — | ホバーで **modal-close-rotate** 風の微回転（任意） | modal-family（mahoyaku） |
| 全行リセット実行 | — | 行を即消しせず **collapse + fade-out**（多数行は stagger を抑えて一括フェード）してから反映 | キャラ削除退場と同系（appear/collapse） |
| コピペ取り込み | 追加行が **appear-slide / FLIP** で順次入場（既存の行追加と同じ） | — | 既存 FLIP / appear-slide |
| キャラ名編集 | span → input を**クロスフェード＋わずかな拡大**で滑らかに切替。確定で名前がふっと更新 | — | hover-feedback 系の微トランジション |
| ColorWheel ポップオーバー | **dropdown-enter-right 相当**（opacity + scale 0.96→1 / 小移動, ~0.18s） | フェード | nav-menu-family（linear-app） |
| 色変更の反映 | 対象キャラの行アクセント（左バー・ドット）が **色トランジション**（`transition: background-color/box-shadow ~0.2s`）でぬるっと変化 | — | hover-feedback（color-shift 系） |

## 5. パース仕様（コピペインポート）

```
1. text を /\r\n|\r|\n/ で分割
2. 各行を trim
3. 空行（trim 後が空）はスキップ（F-75）
4. 先頭キャラ characterId を決定:
     - characters が空なら「キャラ1」を自動作成し、その id を使う（F-76）
     - そうでなければ characters[0].id
5. 残った各行を { id: 生成, characterId: 先頭, text: 行 } として lines の末尾に push（F-74）
```

- Markdown インポート（spec-v1.1）との違い: コピペは `名前:` を解釈せず、**全行を1行=1セリフのプレーンテキスト**として扱い、**先頭キャラ固定**・**末尾追加**。

## 6. 非機能・アクセシビリティ

- **モーダル**: dialog ロール / aria-modal / フォーカストラップ / Esc 閉じ / オートフォーカス / 閉じてトリガーへ復帰。
- **名前編集**: input に `aria-label`、Enter 確定・Esc 取消。
- **色相環**: クリックに加え hex 入力欄でキーボード操作を担保。色変更は当該キャラの行を再描画するが、これは表示更新として妥当（NF-10 の打鍵パスには影響しない）。
- **prefers-reduced-motion**: モーダル/ポップオーバーのアニメは控えめにし、reduce では簡素化。
- 既存テスト（85）と機能・アクセシブル名は壊さない。新規分はテストを追加。

## 7. 確認したい設計判断（着手前に確定）

| # | 論点 | 推奨（既定案） | 代替 |
|---|---|---|---|
| 1 | コピペ取り込みは末尾**追加** or 現台本**置換**？ | **追加**（要望「1行を追加する感じ」より） | 置換（Markdown と同挙動に揃える） |
| 2 | 空行の扱い | **スキップ** | 空セリフ行として残す |
| 3 | キャラ0人のとき | **「キャラ1」を自動作成して取り込む** | ボタン無効＋「先にキャラを追加して」案内 |
| 4 | 色 UI の範囲 | **色相環＋明度スライダー＋hex入力**（実用＋a11y） | 色相環のみ / 彩度も追加 / ネイティブ `<input type=color>`（※色相環でなく四角になる） |
| 5 | コピペボタンの置き場所 | ヘッダーの**独立ボタン** | 「読込▾」メニュー内に「テキストを貼り付け」として追加 |
| 6 | 全行リセットの対象範囲 | **セリフ行のみ削除**（キャラ・プロジェクト名は残す） | 全消し（新規プロジェクト相当：キャラも名前もクリア） |
| 7 | 確認モーダルの既定フォーカス | **キャンセル**（破壊防止） | リセット側 |

> **確定（2026-05-24）**: #1〜#7 すべて上表の「推奨（既定案）」で確定。
> = コピペは末尾追加 / 空行スキップ / 0人時は「キャラ1」自動作成 / 色UIは色相環＋明度スライダー＋hex入力 /
> コピペは独立ボタン / リセットはセリフ行のみ削除 / 確認モーダルの既定フォーカスはキャンセル。
