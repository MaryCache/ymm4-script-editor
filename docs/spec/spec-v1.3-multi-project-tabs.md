# 追加仕様書 v1.3 — プロジェクトタブ（台本の複数管理）

対象バージョン: v1.3.0
作成日: 2026-05-24
基底ドキュメント: requirements.md / design.md / spec-v1.1 / spec-v1.2 / ADR-001
ステータス: **確定（2026-05-24。実装可否=可能、§8 は推奨案で確定 → 実装着手）**

---

## 1. 追加背景

- 1本のアプリで**複数の台本（プロジェクト）をタブで切り替えて管理**したい。回ごと・シリーズごとに台本を並行編集できる。
- これは当初 **明示的にスコープ外**だった（requirements §7「複数プロジェクトの同時管理」/ ADR-001「IndexedDB は複数管理が要件にないため不採用」）。本書で要件に**昇格**し、永続化方針も再検討する。

---

## 2. 実装可否（結論: 可能・ブロッカーなし）

| 観点 | 判定 | 根拠 |
|---|---|---|
| 影響範囲 | 局所 | `useProject` の実消費者は **App.tsx のみ**。各コンポーネントは props 経由でアクティブ台本を操作。ワークスペース層を被せれば UI コンポーネントはほぼ無改修 |
| 永続化 | localStorage 継続で可 | 台本はテキスト主体で軽量。複数でも 5MB 制限に余裕。IndexedDB 等の新依存は不要（オフライン・依存ゼロ維持） |
| データ互換 | 維持 | `Project` 型は不変。`id`/`activeId` は**ワークスペースのラッパ**側に持たせ、`.ymscript`（単体 Project）形式は壊さない |
| 既存データ移行 | 容易 | 旧キー（単体 Project）→ ワークスペース（その1本をアクティブ）へマイグレーション |
| NF-10 | 維持 | タブ切替＝アクティブ台本入替で編集領域は再描画されるが妥当。打鍵パス・LineRow memo は不変 |

→ **特に問題なし。** 主作業はワークスペース状態の追加・タブ UI・マイグレーション。

## 3. 機能要件

### 3.1 タブ操作

| ID | 要件 | 優先度 |
|---|---|---|
| F-110 | 複数のプロジェクトをタブで保持し、クリックで**アクティブを切り替え**られる | 必須 |
| F-111 | 「**＋**（新規プロジェクト）」でからの台本タブを追加し、それをアクティブにする | 必須 |
| F-112 | 各タブに**プロジェクト名**を表示する | 必須 |
| F-113 | タブを**閉じる**（× ）。**行が1件以上ある、または初期キャラ以外のキャラクターが追加されているタブ（= 中身あり）**を閉じる時は **ConfirmDialog で確認**（破棄は元に戻せない）。行が0件かつ追加キャラなしのタブは空とみなし確認なしで閉じる ※§8-3 | 必須 |
| F-114 | **最後の1タブは閉じられない**（常に最低1プロジェクト存在）※§8-4 | 必須 |
| F-115 | アクティブタブを視覚的に区別（色・下線等）。タブが多い時は横スクロール可能 | 必須 |
| F-116 | プロジェクト名の編集（タブ上でのリネーム or 既存のヘッダー入力）※§8-5 | 必須 |
| F-117 | 全プロジェクトは localStorage に自動保存され、次回起動時に**タブ構成ごと復元**（アクティブも記憶） | 必須 |

### 3.2 既存機能との関係

- キャラクター管理・台本編集・コピー/書き出し・コピペインポート・全行リセット・色編集など **既存の全操作は「アクティブなプロジェクト」に対して**動作する（挙動は不変）。
- localStorage 自動保存は「ワークスペース全体」を保存する形に拡張。

## 4. データモデル

`Project` 型は**変更しない**（`.ymscript` 互換維持）。複数管理はワークスペースのラッパで表現する。

```typescript
// 新規: ワークスペース（localStorage 永続化単位）
type WorkspaceEntry = {
  id: string;        // タブ識別子（workspace 内で一意。Project には持たせない）
  project: Project;  // 既存の Project（version/projectName/characters/lines）
};

type Workspace = {
  version: 1;
  activeId: string;          // 現在アクティブな entry の id
  entries: WorkspaceEntry[]; // 1つ以上
};
```

- `id` は `crypto.randomUUID()`。`Project` 内には入れない（ファイル形式・既存テスト不変）。
- 不変条件: `entries.length >= 1`、`activeId` は必ず entries のどれかを指す。

---

## 5. 永続化 ＆ マイグレーション

- 新キー: `ymm4-script-editor:workspace`（Workspace を JSON 保存）。
- 旧キー: `ymm4-script-editor:last-project`（単体 Project）。
- 起動時の復元ロジック:
  1. workspace キーがあれば parse・検証して採用（壊れていれば既定ワークスペースへフォールバック）。
  2. 無ければ旧キーを確認 → あればその Project を1エントリのワークスペースに**移行**してアクティブに（移行後、旧キーは残してもよいが workspace を正とする）。
  3. どちらも無ければ、空の既定プロジェクト1つのワークスペース。
- 保存は `workspace` が変わるたび（debounce 不要レベル）に書き込み。容量超過時は console.error（既存方針踏襲）。

## 6. 状態設計

- **useProject 内部をワークスペース化（公開 API 名は `useProject` のまま）で実装確定**（`useWorkspace` への改名は不採用）。
- 公開するもの:
  - **アクティブ台本のビュー＋既存 mutator**（`project` / `setProjectName` / `addCharacter` / ... / `importPlainText` / `clearAllLines` など、すべて**アクティブ entry に作用**）。← App→各コンポーネントの props は実質不変。
  - **ワークスペース操作**（新規）:
    - `tabs: { id, name }[]`（タブ表示用）、`activeId`
    - `newProject(): void`（空プロジェクト追加＋アクティブ化）
    - `switchProject(id): void`
    - `closeProject(id): void`（最後の1つは no-op。中身チェックは UI 側で確認モーダル）
- 全 mutator は安定参照（既存方針）。アクティブ entry の Project を更新する形に内部実装を変更（`setWorkspace(updater)` で activeId の entry.project を差し替え）。
- `.ymscript` 保存/読込・CSV/Markdown は**アクティブ Project** に対して（既存どおり）。読込は §8-2 参照。

## 7. UI / コンポーネント設計

### 7.1 ProjectTabs（新規）

- タブストリップ（`role="tablist"`、各タブ `role="tab"` `aria-selected`）。`role="tabpanel"` に相当する編集領域コンテナは **ProjectTabs の内側ではなく App 側**に配置する（タブストリップと編集領域は別要素）。
- 配置: **ヘッダーの下の細いタブ行**（推奨）。WCO 時にヘッダーがタイトルバーになるため、タブは別ストリップが収まりがよい ※§8-1。
- 各タブ: プロジェクト名＋× 閉じるボタン。「＋」新規ボタンはタブリスト末尾（最後のタブの直後）に追従。タブ多数時は横スクロール（ホイール/ドラッグ）。
- アクティブタブを色・下線・背景で強調（cold-blue-black＋シアン）。
- アニメ（design-library・v1.3 後 UI 改良を含む実装詳細は `design.md §10.14`）:
  - 新規タブ追加 = **appear-slide**
  - 切替の下線移動 = スライド
  - 閉じる = ゴースト要素を元位置に差し込み**フェード＋幅コラプス**（全削除経路を一元カバー。reduced-motion 時は即時）
  - **＋ボタン**: hover で「＋」装飾が 90度回転。タブ増減時は FLIP でグライド
  - **×ボタン**: tabItem 内側・全高配置。既定 opacity:0、タブ hover/`:focus-within` でフェード出現。最後の1タブで disabled
- すべて `prefers-reduced-motion: reduce` 尊重。

### 7.2 既存への影響

- Header / CharacterPanel / ScriptEditor 等は**無改修**（App が渡すアクティブ Project の props を使うだけ）。
- 閉じる確認は既存 `ConfirmDialog` を再利用。
- プロジェクト名編集は §8-5 の決定により、ヘッダー入力 or タブ上ダブルクリック編集（CharacterPanel の名前編集パターンを流用可能）。

## 8. 確認したい設計判断（着手前に確定）

| # | 論点 | 推奨（既定案） | 代替 |
|---|---|---|---|
| 1 | タブの配置 | **ヘッダー直下の専用タブ行** | ヘッダー内に詰め込む |
| 2 | `.ymscript` / `.md` 読込の挙動 | **新規タブとして開く**（複数管理に自然） | 現アクティブを置換（現行挙動のまま） |
| 3 | 中身のあるタブを閉じる時 | **ConfirmDialog で確認**（中身あり = 行1件以上 or 追加キャラあり。行0件かつ追加キャラなし = 空 = 無確認で閉じる） | 無確認で閉じる |
| 4 | 最後の1タブ | **閉じ不可**（常に1つ以上） | 閉じたら空プロジェクト自動生成 |
| 5 | プロジェクト名の編集場所 | **タブをダブルクリックで編集**（ヘッダー入力は廃止 or 併存） | ヘッダー入力のみ継続 |
| 6 | 永続化 | **localStorage（ワークスペース1キー）** | エントリごとにキー分割 / IndexedDB |
| 7 | タブ並べ替え（D&D） | **スコープ外** | 実装する |

> **確定（2026-05-24）**: #1〜#7 すべて上表の「推奨（既定案）」で確定。
> = タブはヘッダー直下の専用行 / 読込は新規タブで開く / 中身ありタブの閉じるは ConfirmDialog 確認 /
> 最後の1タブは閉じ不可 / プロジェクト名はタブのダブルクリックで編集（ヘッダーの入力欄は併存＝同じアクティブ名を編集）/
> 永続化は localStorage の単一ワークスペースキー / タブ D&D 並べ替えはスコープ外。

## 9. スコープ外（今回）

- タブのドラッグ＆ドロップ並べ替え（他箇所同様 DnD は不採用方針）。
- ワークスペース全体の単一ファイルへの一括エクスポート/インポート（`.ymscript` は単体 Project のまま）。
- プロジェクトの複製、タブのピン留め、未保存インジケータ等の付加機能。
- IndexedDB 化（将来、巨大データが現実になったら再検討）。

---

## 10. 想定タスク分解（実装フェーズの目安）

1. 型追加（`Workspace` / `WorkspaceEntry`）＋ ワークスペースの parse/検証ユーティリティ ＋ テスト。
2. `useProject` → ワークスペース化（アクティブ entry に既存 mutator を作用、`newProject`/`switchProject`/`closeProject`/`tabs`/`activeId` 追加、旧キーからのマイグレーション）＋ テスト。
3. `ProjectTabs` コンポーネント（tablist/tab・新規/切替/閉じる・横スクロール・アニメ・a11y）＋ テスト。
4. App 結線（ProjectTabs 配置、閉じる確認は ConfirmDialog 再利用、§8 の決定反映）。
5. プロジェクト名編集（§8-5 の決定に従う）。
6. アクセシビリティ・全体レビュー（coding-principles → code-reviewer）。
