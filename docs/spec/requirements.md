## 1. 目的・背景

### 1.1 制作者の需要（このアプリを作る動機）

YukkuriMovieMaker4（YMM4）を使った動画制作では、台本まわりで次の3つが分断されている。

1. **YMM4 の台本機能** — 最終的にセリフを CSV（`キャラクター名,セリフ`）等で取り込んで動画化する。
2. **LLM による台本執筆** — ChatGPT 等の LLM にキャラクターとテーマを与え、台本のドラフトを高速に生成させる。
3. **人力での調整** — 生成された台本の言い回し・尺・キャラ割り当て・誤りを、人間が読みやすく直す。

現状、この3者の間には手作業のコピペ・整形・形式変換が挟まり、「執筆 → 調整 → YMM4 取り込み」の往復が煩雑になる。  
**「LLM が書く」「人が直す」「YMM4 が読む」を円滑に橋渡しするツールが欲しい** —— これが制作者（＝本アプリの主ユーザー）の具体的な需要であり、本アプリを作る最大の動機である。

### 1.2 本アプリの役割

このウェブアプリは、その橋渡しを一手に担う。

- **LLM の出力をそのまま取り込む**: Markdown（`名前: セリフ` 形式）で AI 生成台本を読み込み、キャラクターも自動登録する（spec-v1.1）。
- **人が快適に調整する**: キャラクター×セリフを行単位で編集・並べ替え・文字数確認しながら整える。
- **YMM4 へ渡す**: UTF-8 BOM 付き CSV（`キャラクター名,セリフ`）として書き出し、YMM4 にそのまま取り込む。

すなわち、台本の作成〜調整〜CSV 書き出しまでを一元的に行い、**LLM・人・YMM4 の間の摩擦をなくす**ことを目的とする。

## 3. 機能要件

### 3.1 キャラクター管理

| ID | 要件 | 優先度 |
|---|---|---|
| F-01 | キャラクターを名前で登録できる | 必須 |
| F-02 | キャラクターに識別色を自動付与する | 必須 |
| F-03 | キャラクターを削除できる | 必須 |
| F-04 | キャラクターを削除した際、そのキャラクターが割り当てられていたセリフ行は先頭キャラクターに自動変更される | 必須 |

### 3.2 台本編集

| ID | 要件 | 優先度 |
|---|---|---|
| F-10 | セリフ行を追加できる（末尾追加・特定行の後ろに追加。**直後追加のキャラ割当は §9.1 F-63 を正＝直前行を継承**） | 必須 |
| F-11 | セリフ行を削除できる | 必須 |
| F-12 | セリフ行の順番を入れ替えられる（上下移動） | 必須 |
| F-13 | 各セリフ行にキャラクターを割り当てられる | 必須 |
| F-14 | セリフのテキスト入力はシングルライン（単一行）である | 必須 |
| F-15 | 各セリフ行の文字数をリアルタイムで表示する | 必須 |
| F-16 | 台本全体の合計文字数を常時表示する | 必須 |

### 3.3 コピー・エクスポート

| ID | 要件 | 優先度 |
|---|---|---|
| F-20 | 各セリフ行を `キャラクター名,セリフ` 形式で1行コピーできる（spec-v1.1 F-50 に統合。全件コピーは F-51/F-52） | 必須 |
| F-21 | 台本全体を UTF-8 BOM付き CSV（`.csv`）として書き出せる | 必須 |
| F-22 | CSV はコンマ区切り・1行1セリフの形式とする（YMM4の読み込み仕様に準拠） | 必須 |

### 3.4 プロジェクト管理

| ID | 要件 | 優先度 |
|---|---|---|
| F-30 | プロジェクト名を編集できる | 必須 |
| F-31 | プロジェクトを `.ymscript`（JSON）ファイルとして保存できる | 必須 |
| F-32 | `.ymscript` ファイルを読み込んで状態を復元できる | 必須 |
| F-33 | 最後に編集したプロジェクトを localStorage に自動保存し、次回起動時に復元する | 必須 |

## 4. 非機能要件

### 4.1 技術制約

| ID | 要件 |
|---|---|
| NF-01 | バックエンドを持たない。すべての処理はブラウザで完結する |
| NF-02 | 外部 API への通信を行わない |
| NF-03 | ネットワーク接続がない状態でも動作する（PWA・オフライン対応） |
| NF-04 | デスクトップにインストール可能である（PWA） |

### 4.2 パフォーマンス

| ID | 要件 |
|---|---|
| NF-10 | 台本 500 行程度での操作がストレスなく動作する（入力遅延が体感できないこと） |
| NF-11 | 初回ロードを含むページ表示が 2 秒以内であること（ローカルホスト環境） |

> **NF-10 の検証基準**: 1セリフの打鍵で「編集中の行以外」が再描画されないこと（`React.memo` + 安定ハンドラ + FLIP の構造変化時のみ実行で担保）。500行を流し込んだ状態で `src/perf/scale.test.tsx` と React DevTools Profiler により確認する。
> **NF-11 の検証基準**: `npm run preview`（または本番 HTTPS）で初回表示が 2 秒以内。ビルド成果物は JS ~210KB / gzip ~66KB。

### 4.3 互換性

| ID | 要件 |
|---|---|
| NF-20 | 最新版 Chrome / Edge で動作する（主要ターゲット） |
| NF-21 | モバイルブラウザは対象外（デスクトップ利用想定） |

## 5. データ仕様

### 5.1 プロジェクトファイル形式（`.ymscript`）

```json
{
  "version": 1,
  "projectName": "string",
  "characters": [
    { "id": "string", "name": "string", "color": "string" }
  ],
  "lines": [
    { "id": "string", "characterId": "string", "text": "string" }
  ]
}
```

### 5.2 CSV エクスポート形式

```
キャラクター名,セリフテキスト
霊夢,今日はCSVの使い方を解説するわ！
魔理沙,しっかり覚えろよ！
```

- 文字コード: UTF-8 BOM付き（Excel / YMM4 の文字化け防止）
- ヘッダー行なし
- ファイル名: `{プロジェクト名}.csv`

## 7. スコープ外（現バージョン）

- セリフのアクセント・読み調整機能
- ドラッグ＆ドロップによる行の並べ替え（上下ボタンで代替）
- 複数プロジェクトの同時管理（**v1.3 で要件昇格済み。spec-v1.3 参照**）
- 音声プレビュー
- Undo / Redo
- 行の複数選択・一括操作
- **読み上げ秒数の自動見積もり（不採用）** — 当初は将来検討。検証で文字数と読み上げ秒数の関係は線形だった（きりたん100行=6:17 ≒ 6.72字/秒）が、読み上げ速度は声・再生速度・各自の設定で変わり万人共通の固定値を持てない。係数をユーザー設定にする案も本ツールには過剰と判断し、2026-05-24 に不採用とした（行・全体の文字数表示で相対的なペース感は足りる）。

## 8. 用語定義

| 用語 | 定義 |
|---|---|
| 台本 | キャラクターとセリフの対のリスト |
| セリフ行 / ライン | 台本の1単位。キャラクター1人 + テキスト1行。**「行」と「ライン」は同義**（UI 表示・本書の散文は「行」、コード/型名は `Line`/`line` を用いる） |
| プロジェクト | プロジェクト名 + キャラクター一覧 + 台本セット |
| `.ymscript` | 本アプリ独自のプロジェクト保存形式（JSON） |

### 9.1 追加された機能要件

| ID | 要件 | 優先度 | 備考 |
|---|---|---|---|
| F-60 | 台本の**行数（ライン数）**を合計文字数と並べて常時表示 | 必須 | F-16 に併記 |
| F-61 | キャラクター選択は**独自ドロップダウン**（OS標準 select ではない）。色ドット＋名前＋シェブロン、キーボード操作（↑↓/Enter/Escape/外側クリック）対応 | 必須 | F-13 の UI 具体化 |
| F-62 | 各セリフ行に行内アクション（**上/下移動・1行コピー・直後に追加・削除**）を備える | 必須 | F-10〜F-12/F-20 の UI |
| F-63 | 「特定行の直後に追加」した行は**その行のキャラクターを引き継ぐ**（末尾追加は先頭キャラ） | 必須 | ※当初設計の「先頭キャラ固定」から変更 |

| F-66 | コンテンツがスクロール可能な時、**上下のスクロール促し**表示と**「一番上に戻る」**ボタンを表示 | 推奨 | |
| F-67 | コピー失敗時は**ユーザーに通知**（alert）。design §8「赤くする」の代替 | 必須 | |
| F-68 | 起動時に**オープニング演出**（タイトルロゴ＋放射モーション）。sessionStorage でセッション中1回、`prefers-reduced-motion` で非表示 | 任意 | 動作抑制は NF-31 の個別適用 |

### 9.2 追加された非機能要件

| ID | 要件 |
|---|---|
| NF-30 | **アクセシビリティ**: アイコンのみボタンに `aria-label`、フォーム要素にラベル、独自ドロップダウンは listbox/option ロール＋キーボード操作、装飾要素は `aria-hidden` |
| NF-31 | **prefers-reduced-motion** を全アニメーションで尊重（OS で動きを減らす設定時は静止/非表示） |
| NF-32 | PWA インストール時、**Window Controls Overlay** でネイティブウィンドウ風（ヘッダーを自前タイトルバー化）。Edge/Chrome デスクトップ。secure context（HTTPS / localhost）必須 |
| NF-33 | **外部リソース**（フォント/CSS/JS/CDN）を読み込まない。新規ランタイム依存を増やさない（フォントは同名スタックでシステムフォールバック） |
| NF-34 | 保存時、ファイル名の不正文字をサニタイズ（パス区切り等→`_`、空は `untitled`） |
| NF-35 | **GitHub Pages**（サブパス `/ymm4-script-editor/`）に **GitHub Actions** で自動デプロイ。HTTPS 配信。Vite `base` 対応済み |

### 9.3 データ仕様の補足（§5 への追補）

- **CSV**: セリフ内の **半角カンマのみ**を全角カンマ（，）へ変換（列ズレ防止）。読点「、」など他の句読点は**保持**。改行/CR は半角スペースへ畳む。**キャラクター名列にも同変換**を適用。
- **Markdown**（spec-v1.1）: 出力はフロントマター付き完全形式。読み込みは現状態を**置換**（**v1.3 以降は置換せず新規タブとして開く。spec-v1.3 §8-2 参照**）。区切りは `名前: セリフ`（コロン＋半角スペース）のみ。ID は読み込みごとに新規採番（保持しない）。

### 9.4 ブランド・配色（実装で確定）

- 全体配色は **cold-blue-black** に変更。
  - 背景: `#0f1117`（当初）→ **`#00101d`**
  - アクセント: `#5b8dff`（当初）→ **シアン `#107dc8`→`#2bb4e6`→`#58d3f0`**
- アイコン（`icon-512/192`・`favicon`）・ヘッダーロゴ・オープニングロゴはユーザー提供の透過 PNG。
